# §47. Calls get a second UDP path; the hy2 callback stops blocking (2026-11-11, plan F, package A)

Until now every user's UDP (Telegram calls) went through hy2 alone, so a network that throttles UDP left calls nowhere to go, and a busy bot.db could stall the hy2 handshake. Package A of `docs/IMPROVEMENT_PLAN.md` section F.

- **The calls group** (`SubscriptionService._collect_outbounds`) holds, in priority order: hy2; Reality and the DE reserve, which carry UDP inside their TCP stream (xudp); Turbo (hy2t) last. ws and ShadowTLS never enter it. Demo profiles have neither Reality nor the reserve, so their group is still hy2 alone. A second path for demo is the owner's decision (plan F, A5), not taken.
  - **Clash** `Calls` is a `fallback` group: the first live server in that order. It also takes the `emergency` / `mirror-<n>` copies of its own servers, after its own, via one end-anchored `filter` (mihomo re-sorts a group by its filters when there are several).
  - **sing-box** has no fallback type. The `calls` urltest gets `tolerance` 30 000 ms (`_CALLS_URLTEST_TOLERANCE_MS`), above any delay it can measure (15-s test timeout). sing-box 1.11 then keeps the first live server in list order and switches only when it fails a check. The comparison is uint16 there (`delay + tolerance`): past 50 535 it wraps and the group chases the fastest again.
  - **Demotions** (A2): `build_singbox_config` and `build_clash_config` take `demoted` (`get_auto_demotions` for the request's network, as for Clash before) and move those protocols to the end of the calls group (`_calls_order`). hy2 demoted on a network → Reality leads that network's calls. `/sub` and the SOS kit pass it to both builders.
- **Why hy2 was alone, and why that no longer holds.** The old comment feared that a Reality client not attached to the inbound passes the url test through the TLS masquerade. Stand `tests/integration/test_calls_stand.py` (`requires_docker` + `requires_network`) runs the bot's own profiles in mihomo 1.19.33 and sing-box 1.11.15 against xray 26.6.22, the exit's version on 2026-11-10. An unknown uuid fails the check (xray: "invalid request user id"). Both groups pick hy2 while it works and Reality once hy2 stops. Every key sits on every exit inbound anyway (88 of 88 on 2026-11-10).
  - mihomo's fallback returns to hy2 when it comes back. sing-box stays on Reality until Reality fails (sticky). It notices a dead hy2 only on its periodic check, up to 3 min. So in Karing a single failed hy2 check (say, at app start) keeps calls on Reality for the rest of the session.
  - **Limit:** under mobile UDP throttling hy2 still passes the tiny url test while its streams die within seconds (§25), so neither group leaves it. Only a demotion helps there (R4 puts Reality first for that network), and only after the client's next profile fetch.
- **ShadowTLS is TCP-only in the sing-box profile** (A3): its Shadowsocks outbound has `network: tcp`, as the Clash form had `udp: false`. Hiddify drops the groups and balances UDP over every outbound; it used to put some UDP flows on ShadowTLS, where UDP cannot pass. This changes the Hiddify profile's bytes, by the owner's decision on package A.
- **`/api/hy2/auth`** (A4, `WebAppServer._hy2_auth_common`):
  - the users row is read on a worker thread (`_hy2_user_row` → `_hy2_lookup_user`). On the event loop a locked bot.db (5-s busy timeout) held every request the web server had in flight;
  - the last-geo update and the `hy2_auth_log` row are written after the answer, on a thread of their own (`_spawn_hy2_record`; not asyncio's default pool, which the lookups use). Past 500 queued writes a new one is dropped;
  - when the read fails, the decision uses the last row this key resolved to (`bot/services/hy2_auth_rows.py`), if it is under 15 min old. The status, tier and expiry gates still run on it. A key not seen since the start fails closed, as before. The row is dropped by a good read without a row, by `revoke_user_key` and by every `StateMachine` status change, so a key banned or downgraded while its client stays connected is read again, never let in from memory.
  - A bot restart no longer refuses new hy2 connections once exit runs the auth relay (A6, §56).
- **Tests:** `tests/integration/test_calls_udp_paths.py` (builders, `/sub` and the kit on a real sqlite, the hy2 callback with a broken and a slow bot.db), the stand above, updated cases in `test_clash_profile.py`, `test_clash_channels.py` and `test_web_server.py`. 23 mutants killed (hy2-only collapse, priority order, tolerance at 50 and past the wrap, fallback vs url-test, filter anchor, `network: tcp`, demotions on each path, the remembered row, writes before the answer, lookup on the loop), restored by reverse text replacement with a hash check.
