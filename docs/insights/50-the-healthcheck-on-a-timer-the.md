# §50. The healthcheck on a timer, the agent as an adviser, usage and hy2 sessions (2026-11-11, plan F, package D)

Package D of `docs/IMPROVEMENT_PLAN.md` section F. Each part runs only once installed: the healthcheck timer on entry and the reporter on exit, both in place since 2026-11-11.

- **D1, the healthcheck on its own.** `scripts/protocol_healthcheck.py` gets `findings` (`findings_for(layers)`, pure): facts that break users before the probes go dark, judged whatever the probe verdict says.
  - The facts: the Reality dest cert (> 7000 B warn, > 8000 B critical), missing entry UDP DNAT for hy2 (critical) or hy2t (warn), missing exit hop REDIRECTs (warn), hysteria / hysteria-turbo / shadow-tls units not active, a BROKEN panel field audit (critical). Since 2026-11-11 also what a tunnel user can reach on exit itself: `hy2_acl:<unit>`, `xray_api_exposed`, `xray_api_polling`, `exit_guard_unreadable` (§52). Since 2026-11-15, `hy2_relay`: a running hysteria asks the auth relay and the relay is down (§56).
  - Since 2026-11-13, the two servers `setup_ssh_exit.sh` and `setup_xhr_exit.sh` run on exit (§51), each a container plus a root timer that syncs its users from the bot every 2 min (`exit_servers()`, `EXIT_SERVERS`):
    - `exit_server:<name>`: the container is not running (a crash loop is named), or it is gone while its sync timer is still installed. Critical for `xhr-exit` while xhr is on in the cascade (every xhr user is cut off); warn for `ssh-exit` (the emergency path only).
    - `exit_sync:<name>`: the sync timer is not active, the last run failed (`Result` other than success), or no run finished for 10 min (`EXIT_SYNC_STALE_S`, from the service's monotonic exit time and exit's `/proc/uptime`). Warn: a stuck sync only freezes the user list.
    - Nothing is said about a server whose protocol is switched off (xhr until it is on), or one never installed (no container and no sync unit). Without layer A the cascade is unknown, so xhr-exit's keys are unjudged, and so is a sync caught mid-run (systemd zeroes its exit time and result then) or any answer that could not be read: "could not look" is never "fixed".
    - The layer-C script sends the raw `docker inspect` / `systemctl show` answers; the verdict is the pure `exit_servers()` on entry. `parse_exit_json` keeps only the keys it lists, so a new layer-C fact needs its key there (`exit_servers`), or it is dropped and judged "not looked at" forever.
    - Whether sshd and xray actually serve is the probes' job: xhr's once xhr is switched on (§51 E3), the SSH path's `ssh` probe since 2026-11-15 (§51 E4, through the mihomo sidecar).
  - `--post URL` sends the report, without `layers_raw`, with `X-DPI-Token` = `DPI_REPORT_TOKEN` read from `/opt/vpn-bot/.env`.
  - `systemd/protocol-healthcheck.{service,timer}`: every 15 min, as root on ENTRY, `SuccessExitStatus=1 2`, about 15 s of the single core. Install with `sudo /opt/vpn-bot/scripts/install_protocol_healthcheck.sh` (`--remove` takes it out). The timer runs root-owned COPIES of the script and of `bot/services/probe_rules.py` in `/usr/local/lib/nekovpn-healthcheck/`, never the rsync target, which belongs to the deploy account (§36); re-run the installer after either file changes. The unit adds NoNewPrivileges, PrivateTmp and ProtectSystem=full.
  - The bot stores reports in `healthcheck_reports` (`POST /api/healthcheck/report`, the exit report's token, ≤ 256 KB, kept 7 days). `check_healthcheck` turns each finding into `healthcheck:<key>`, with the script's next command in the detail and no agent turn.
  - **"Could not look" is never "fixed".** A report older than 45 min pages `healthcheck:stale` (critical) and judges no finding: every open finding keeps its state (AlertManager's judged set, §48). Each finding names its layer (`a` bot db, `b` entry, `c` exit); a finding of a layer that could not look this run (ssh to exit timed out) keeps its alert as it is. A layer that could not look three runs in a row pages `healthcheck:blind` (critical), whatever the exit code (exit unreachable while ws is degraded gives code 1). A failed read judges nothing. No report ever means the timer is not installed, and the check says nothing; retention always keeps the newest report, so a dead timer does not heal itself after a week. Findings about a protocol the operator switched off (hy2t's unit, DNAT, hop rules) are not raised.
- **D2, the agent proposes, the admin presses** (`bot/services/agent_actions.py`).
  - The protocol prompt asks for one more line: `ДЕЙСТВИЕ: restart_xray | demote <protocol> | нет`. The bot parses it; anything off the list is ignored. It shows a ▶️ button under the diagnosis: `agent_act:<action>:<arg>:<unix ts>`. The line must be exactly the action (trailing punctuation aside): «restart_xray не нужен» gives no button.
  - `AgentActionHandler` (admins only; the data is checked again; buttons older than 2 h are refused) runs ordinary code. `restart_xray` is the panel's restart via `XUIService._run_sync(api.restart_xray())`; `demote` is a 6-h hand demotion (`cascade_manual`, §49). It edits the message with the result and audits `agent_action_<action>`. A button runs once: a double tap, or a press after a restart, finds its earlier press (process memory, then the audit row, which carries the button) and answers «уже выполнено». When Telegram refuses the edit, the result goes to the same chat and topic, never the admin's PM.
  - The model runs nothing itself: on 2026-08-30 it proposed an ALTER TABLE on prod.
- **D3, who uses which protocol.** Each exit report carries a `usage` block: every inbound each user was accepted on in the window, with the count (the presence block keeps only the last tag, and a client's url test through another server could put the user there). The bot adds it to `protocol_usage(day, chat_id, proto, conns)` (kept 90 days) after the dpi rows are stored, so a window re-sent after a 500 adds nothing twice; an older reporter's presence block stands in.
  - `/usage [days]` (1–30, default 7) prints distinct users per network (`users.last_asn`, «?» = never fetched a profile from its network) × protocol. A user counts under an xray protocol that carried ≥ 20 % of their connections in the period (url tests are a handful). hy2 = an authenticated session in `hy2_auth_log` (hy2t included; that log cannot tell them apart), over the same calendar days.
- **D4, hy2 session lengths.** `scripts/exit_dpi_reporter.py` reads the hysteria journal (`journalctl -o json -u hysteria -u hysteria-turbo --after-cursor`).
  - It pairs `client connected` / `client disconnected` inside one hysteria PROCESS (unit, boot id, pid): a restart logs no disconnect for the connections it killed, and pairing across it shifted every later session. A disconnect closes the connect with the same addr, else the newest open one (the addr changes with port hopping). Open connects carry over in its state, are forgotten after 24 h, and the probe client is left out.
  - It sends `hy2_sessions: [{id, unit, duration_s, error, ended_at}]` with the report; the cursor advances only when the bot took it. When the journal was last read over 30 min ago (the reporter was down, or the bot refused its reports), the cursor is dropped and the read starts 10 min back, so a backlog can never run past the timeout or MemoryMax and take the report with it; a failing or slow journalctl starts over the same way, entries older than the cursor's are skipped, and a pairing error never costs the report.
  - A quiet journal is no outage: the cursor's own entry may be hours old while the reporter runs every 5 min. Until 2026-11-11 the 30 minutes were the cursor entry's age, so 30 quiet minutes forgot every open connect, and a session open across them never reached the bot: 8 of the 33 sessions over 30 min in a week of exit's journal. The state keeps `journal_read_ts` for this; a state written without it falls back to the cursor's time once.
  - hysteria colours its log level, so `journalctl -o json` gives its MESSAGE as an array of bytes, not a string. The reporter decodes it (PR #47); before that it paired nothing.
  - The bot stores `hy2_sessions` (reason normalized: idle-timeout / closed-by-server / closed-by-client / timeout / reset / other; kept 30 days). `/protocols` adds «⏱ hy2 сессии за 24 ч: N, медиана …, ≥ 30 мин — …%, чаще всего кончаются: …». It keeps the journal's own end time (`ended_at`; a day of backlog used to be stamped "now") and a unique key on (instance, user, end, length), so a re-sent window stores no session twice.
  - **Exit-side**: copy the reporter to exit (`/usr/local/bin`), as for §48.
