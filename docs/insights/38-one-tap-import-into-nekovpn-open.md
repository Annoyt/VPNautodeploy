# §38. One-tap import into NekoVPN: `/open/<token>` (2026-10-25)

The client registers `nekovpn://install-config?url=<profile>` (Android manifest: VIEW + BROWSABLE) and answers it with one «Добавить профиль?» dialog. Telegram buttons take only http(s), so `bot/services/neko_client.py` + `WebAppServer.handle_open` serve `GET /open/<token>` (the /sub token, its 404 / 410): a page whose button is an Android intent link `intent://install-config?url=<FlClash-format /sub>#Intent;scheme=nekovpn;package=com.nekovpn.client;S.browser_fallback_url=<release page>;end` — the installed app opens with the profile, Chrome falls back to the release page otherwise; a copy-the-link fallback below. No automatic jump to the app: Chrome wants a user gesture for app links, and Telegram's in-app browser may replace the page with an error. Headers: `no-store`, `Referrer-Policy: no-referrer` (the download link must not carry the token away), `noindex`, CSP with the page's only script allowed by hash. The «📲 Открыть в NekoVPN» button is the FIRST row of the key card and /sub for every key holder on Android (since 2026-10-31, with the §43 demo allowance), and on other platforms but iOS for `app_settings.client_testers` (the §37 list) only. Tests: `tests/integration/test_neko_client.py` (the intent parsed back the way Android and the app's LinkManager read it, the CSP hash recomputed from the served script); 14 mutants killed by reverse text replacement (§28).
