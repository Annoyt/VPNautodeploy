# §60. The users' address apart from the dashboard: `SUB_PUBLIC_URL` (2026-11-18)

Until now one setting, `WEBAPP_URL`, named both the admins' dashboard and everything users fetch. It pointed at exit's Caddy (`autonekovpn.duckdns.org:9443`). Once exit's IPv4 was blocked from Russia (§59), Russian users could no longer import or refresh a subscription from it, and new installs could not fetch the profile's rule sets.

- **`SUB_PUBLIC_URL`** (env; compose passes it): the base of what users fetch. `bot/utils/public_url.py:public_base_url` returns it, else `WEBAPP_URL`, without a trailing slash; a non-string value counts as unset.
  - On it: the subscription link (`build_subscription_url`, and so /sub, the key card, the SOS and kit links, letters), the sing-box rule sets, the Clash rule-providers (`/lists/…`), the emergency proxy-provider, the telemetry providers and their `/probe/…` checks, the testers' `/probe-big`, `/open/<token>`, `/app`, `/apk`, and the `/list` overview's "раздаются:" line.
  - On `WEBAPP_URL`: the dashboard (`/admin`, the `/start` admin button, the Mini App menu button) and the admin link after a bot-token change.
  - `hop_tls.py verify` also checks `SUB_PUBLIC_URL` when it differs from `WEBAPP_URL`.
  - Empty, or equal to `WEBAPP_URL`, every profile is byte for byte what it was.
- **The address on entry** is `https://radar.nekoweather.xyz:8443`. The name already points at entry (it is hy2's host), and its Let's Encrypt certificate is renewed on exit (acme.sh, Cloudflare DNS). exit's `nekovpn-push-certs.path` copies it to entry's `/etc/ssl/decoy` on every renewal; entry's `/usr/local/sbin/nekovpn-install-cert` checks the pair, installs it and reloads nginx, putting the old pair back if nginx refuses. Before 2026-11-18 entry's copy had expired on 2026-09-06. The same push puts `sub.nekoweather.xyz` into `/etc/ssl/sub-mirror` for the Cloudflare mirror's origin, which moves to entry next.
  - haproxy on :8443 routes by SNI: Reality's names to exit, `gateway.icloud.com` to xhr-exit, everything else to the decoy nginx on 127.0.0.1:18443, which shows wttr.in.
- **Rollout on entry** (after the deploy):
  1. In nginx's `decoy.conf`, a location sends `/sub/`, `/lists/`, `/probe/`, `/probe-big`, `/open/`, `/app`, `/apk`, `/neko/` and `/api/neko/` to the bot at 127.0.0.1:8080, with `X-Forwarded-For` set to the client's address. `/rule-sets/` is served from a copy of exit's `/var/lib/vpn-bot/rule-sets`. Everything else stays the weather decoy.
  2. The client's address comes over PROXY protocol: `send-proxy-v2` on haproxy's decoy server line, plus `listen … proxy_protocol`, `set_real_ip_from 127.0.0.1` and `real_ip_header proxy_protocol` in nginx. Without it the bot sees 127.0.0.1, records no network, and orders profiles by the stored one. Reload nginx first, then haproxy: the decoy errors for that second, while Reality and xhr do not notice.
  3. In entry's `.env`, set `SUB_PUBLIC_URL=https://radar.nekoweather.xyz:8443`, and add it to `SUB_MIRROR_URLS` so the NekoVPN app learns it from `nekovpn-mirrors`. Entry's compose is hand-kept: add `- SUB_PUBLIC_URL=${SUB_PUBLIC_URL:-}` there. Then run `docker compose up -d --no-deps vpn-bot`.
  4. Check with `hop_tls.py verify`, which covers the public address too.
- **Users' stored links** still name the old domain. NekoVPN falls back to its mirrors by itself. Hiddify, Karing and FlClash users re-import the link from /sub; a broadcast is the owner's call.
- **Tests:** `tests/integration/test_public_url.py` (real sqlite: the helper; every URL of both profiles; the links, the /app page, the /sub message; the dashboard button; byte-identical profiles when unset; the lists overview; verify). 16 mutants killed: each call site back on `WEBAPP_URL`, the helper's order, type check and slash, and verify's target and its dedupe. Restored by positional replacement with a hash check.
